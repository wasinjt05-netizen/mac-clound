## 1. บทนำและแนวทางการทดสอบ (Introduction & Testing Guidelines)

เอกสารฉบับนี้กำหนด **เกณฑ์การยอมรับระบบ (Acceptance Criteria)** สำหรับโครงการ **Mactile (MVP)** เพื่อใช้เป็นมาตรฐานในการตรวจสอบ ประเมิน และตรวจรับการส่งมอบระบบ (User Acceptance Testing - UAT) โดยเขียนในรูปแบบ **Gherkin Syntax (Given-When-Then)** และตารางเกณฑ์ประเมินแบบวัดผลได้ชัดเจน (Measurable & Testable)

## 2. เกณฑ์การยอมรับเชิงหน้าที่ (Functional Acceptance Criteria)

### 2.1 โมดูลที่ 1: ระบบจองคิวและการเข้าถึง (Queue Booking & Access Management)

#### AC-1.1: การแสดงรายการเครื่องและสถานะว่าง (Viewing Available Hosts & Slots)
* **Given (กำหนดให้):** ผู้ใช้งานล็อกอินเข้าสู่ระบบ Mactile และเปิดหน้าเลือกเครื่อง
* **When (เมื่อ):** ผู้ใช้เลือกดูรายการเครื่องและตารางเวลา (Slot View)
* **Then (ผลที่ต้องเกิดขึ้น):** 
  - ระบบต้องแสดงรายการเครื่องทั้งหมด พร้อมสถานะปัจจุบัน (`Available`, `In-Use`, `Resetting`, `Maintenance`, `Offline`)
  - ตารางเวลาต้องแสดงช่วงเวลาที่ถูกจองแล้ว (Booked) และช่วงเวลาที่ยังว่างอยู่ (Available) อย่างถูกต้อง

#### AC-1.2: การจองคิวสำเร็จ (Successful Booking)
* **Given (กำหนดให้):** ผู้ใช้เลือกเครื่องที่มีสถานะเปิดรับการจอง และเลือกช่วงเวลาที่ยังว่างอยู่ และไม่เกินโควตารายวัน
* **When (เมื่อ):** ผู้ใช้กดยืนยันการจอง (Confirm Booking)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ระบบบันทึกการจองลงฐานข้อมูล พร้อมปรับสถานะของสล็อตเวลานั้นเป็น `Reserved`
  - ผู้ใช้ได้รับข้อความแจ้งเตือน "จองคิวสำเร็จ" และรายการจองปรากฏในแท็บ "คิวของฉัน (My Bookings)"
  - ผู้ใช้อื่นจะไม่สามารถเลือกจองในช่วงเวลาเดียวกันซ้ำได้

#### AC-1.3: การป้องกันการจองซ้ำซ้อนและจำกัดโควตา (Conflict & Quota Prevention)
* **Given (กำหนดให้):** มีผู้ใช้ 2 คนพยายามกดยืนยันการจองสล็อตเวลาเดียวกันพร้อมกัน หรือผู้ใช้ใช้งานเกินโควตาประจำวัน
* **When (เมื่อ):** ผู้ใช้คนที่สองส่งคำขอจองหลังจากสล็อตถูกจองไปแล้ว
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ระบบต้องปฏิเสธคำขอของคนที่สอง และแสดงข้อความแจ้งเตือน "ช่วงเวลานี้ถูกจองแล้ว กรุณาเลือกช่วงเวลาอื่น"
  - ป้องกันการเกิด Race Condition หรือ Overbooking โดยสมบูรณ์

#### AC-1.4: การแจ้งเตือนนับถอยหลังและใกล้หมดเวลา (Countdown & Expiry Warning)
* **Given (กำหนดให้):** ผู้ใช้กำลังอยู่ในช่วงเวลาเซสชันการใช้งาน
* **When (เมื่อ):** เวลาการใช้งานเหลือ 5 นาทีสุดท้าย
* **Then (ผลที่ต้องเกิดขึ้น):**
  - หน้าต่างเว็บแอปพลิเคชันต้องแสดงแถบเตือนสีเหลือง/ส้ม พร้อมนับเวลาถอยหลัง (Countdown Timer)
  - แสดงปุ่มตัวเลือก "ขอต่อเวลา (Extend)" และ "คืนเครื่อง (Release)" ชัดเจน

#### AC-1.5: การคืนเครื่องก่อนเวลา (Early Session Release)
* **Given (กำหนดให้):** ผู้ใช้งานทำงานเสร็จก่อนหมดเวลาการจอง
* **When (เมื่อ):** ผู้ใช้กดปุ่ม "คืนเครื่องก่อนกำหนด (Release Host)" และยืนยันในกล่องข้อความ
* **Then (ผลที่ต้องเกิดขึ้น):**
  - เซสชันการใช้งานของผู้ใช้จะถูกยุติลงทันที
  - ระบบสั่งเริ่มกระบวนการ Reset สภาพแวดล้อมเครื่องเป้าหมายโดยอัตโนมัติ
  - สถานะของเครื่องเปลี่ยนเป็น `Resetting` ทันที

#### AC-1.6: การขอต่อเวลาการใช้งาน (Session Extension)
* **Given (กำหนดให้):** ผู้ใช้ต้องการใช้งานต่อ และตรวจสอบแล้วว่าไม่มีคิวของผู้ใช้อื่นจองต่อในช่วงถัดไป
* **When (เมื่อ):** ผู้ใช้กดปุ่ม "ขอต่อเวลา (Extend Session)" (เช่น เพิ่ม 30 นาที)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ระบบขยายเวลาสิ้นสุดของเซสชันออกไปตามที่ระบุ และอัปเดตเวลาบนตัวนับถอยหลัง
  - หากมีคิวผู้อื่นรออยู่ ระบบต้องแสดงข้อความปฏิเสธ "ไม่สามารถต่อเวลาได้เนื่องจากมีคิวถัดไปรออยู่"

### 2.2 โมดูลที่ 2: ระบบจัดการและรีเซ็ตสภาพแวดล้อมเบื้องต้น (Environment Management & Basic Reset)

#### AC-2.1: การทำความสะอาดไฟล์ชั่วคราวและแคช (Workspace Cleanup)
* **Given (กำหนดให้):** เซสชันการใช้งานสิ้นสุดลง (หมดเวลา หรือผู้ใช้กดคืนเครื่อง)
* **When (เมื่อ):** Host Agent ได้รับคำสั่ง Reset และรันสคริปต์ทำความสะอาด
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ไฟล์ในโฟลเดอร์ทำงานชั่วคราว, `Downloads`, แคชของเบราว์เซอร์, ไฟล์โปรเจกต์ของผู้ใช้คนก่อนหน้า ต้องถูกลบทั้งหมด
  - ไม่มีไฟล์หรือข้อมูลส่วนบุคคลของผู้ใช้คนก่อนหน้าหลงเหลืออยู่ในโฟลเดอร์ปลายทาง

#### AC-2.2: การปิดและล้าง Process ที่ตกค้าง (Process Termination)
* **Given (กำหนดให้):** มีการเปิดแอปพลิเคชัน, Terminal Shell, Build Script หรือ Background Process ทิ้งไว้
* **When (เมื่อ):** สคริปต์รีเซ็ตเริ่มทำงาน
* **Then (ผลที่ต้องเกิดขึ้น):**
  - แอปพลิเคชันทั้งหมดที่เปิดโดยผู้ใช้ (Non-system Processes) จะถูกปิด/Kill ทันที
  - ตรวจสอบ Process List แล้วพบว่ามีเฉพาะ System Services ที่จำเป็นต่อการทำงานของระบบและ Host Agent เท่านั้น

#### AC-2.3: การคืนค่าสภาพแวดล้อมสู่ Baseline (Baseline Restore)
* **Given (กำหนดให้):** มีการเปลี่ยนแปลงตัวแปรสภาพแวดล้อม (Environment Variables) หรือการตั้งค่าชั่วคราว
* **When (เมื่อ):** สคริปต์รีเซ็ตทำงานเสร็จสิ้น
* **Then (ผลที่ต้องเกิดขึ้น):**
  - การตั้งค่าระบบ สภาพแวดล้อม CLI และการกำหนดค่าพื้นฐานจะถูกคืนค่ากลับสู่ Baseline Snapshot ที่กำหนดไว้

#### AC-2.4: การตรวจสอบความพร้อมหลังการรีเซ็ต (Post-Reset Health Check)
* **Given (กำหนดให้):** สคริปต์รีเซ็ตทำงานเสร็จสิ้น
* **When (เมื่อ):** Host Agent รันการทดสอบ Self-Health Check (ตรวจสอบ Disk Space, Network Connection, Remote Service Status)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - หากผ่าน: Host Agent ส่งสถานะ `Reset Success` ไปยังเซิร์ฟเวอร์ และเซิร์ฟเวอร์ปรับสถานะเครื่องเป็น `Available`
  - ใช้เวลาในกระบวนการรีเซ็ตทั้งหมดไม่เกิน 60 วินาที

#### AC-2.5: การรับมือเมื่อรีเซ็ตล้มเหลว (Fallback to Maintenance on Reset Failure)
* **Given (กำหนดให้):** สคริปต์รีเซ็ตพบข้อผิดพลาด รันไม่สำเร็จ หรือใช้เวลาเกินกำหนด (Timeout)
* **When (เมื่อ):** สคริปต์ส่ง Error Code หรือเซิร์ฟเวอร์ตรวจพบว่า Reset Timeout
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ระบบเปลี่ยนสถานะเครื่องเป็น `Maintenance` โดยอัตโนมัติ
  - ปิดกั้นไม่ให้คิวถัดไปเข้าใช้งาน และแสดงการแจ้งเตือน Error Alert บน Admin Dashboard

### 2.3 โมดูลที่ 3: การเชื่อมต่อรีโมทด้วยโปรแกรมสำเร็จรูป (Remote Connection Integration)

#### AC-3.1: การแจกจ่ายข้อมูลการเชื่อมต่อชั่วคราว (Credential Dispatching)
* **Given (กำหนดให้):** ผู้ใช้ถึงคิวการใช้งานตามช่วงเวลาที่จองไว้
* **When (เมื่อ):** ผู้ใช้กดเข้าสู่หน้า "ห้องทำงานของฉัน (Active Session)"
* **Then (ผลที่ต้องเกิดขึ้น):**
  - ระบบแสดงข้อมูลที่จำเป็นสำหรับการรีโมท ได้แก่:
    1. Connection ID / Target IP & Port
    2. One-Time Temporary Password / Access Token
    3. คำแนะนำวิธีเปิดโปรแกรมรีโมทสำเร็จรูป (เช่น RustDesk, VNC, RDP, SSH)

#### AC-3.2: การเชื่อมต่อสำเร็จผ่านโปรแกรมรีโมท (Successful Remote Connection)
* **Given (กำหนดให้):** ผู้ใช้เปิดโปรแกรมรีโมทสำเร็จรูปบนเครื่องของตนเอง และกรอก Connection ID พร้อม Temporary Password ที่ได้รับ
* **When (เมื่อ):** ผู้ใช้กดยืนยันการเชื่อมต่อ (Connect)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - สามารถเชื่อมต่อและมองเห็นหน้าจอ/Terminal ของเครื่องปลายทางได้อย่างราบรื่นและตอบสนองได้ตามปกติ

#### AC-3.3: การสุ่มเปลี่ยนรหัสผ่านใหม่ทุกรอบ (Password Rotation)
* **Given (กำหนดให้):** เซสชันของผู้ใช้คนก่อนหน้าสิ้นสุดลง และเครื่องผ่านการรีเซ็ต
* **When (เมื่อ):** คิวของผู้ใช้คนใหม่เริ่มต้นขึ้น
* **Then (ผลที่ต้องเกิดขึ้น):**
  - Host Agent สุ่มสร้างรหัสผ่านการเชื่อมต่อชุดใหม่ (Random One-time Password) และอัปเดตลงโปรแกรมรีโมท
  - รหัสผ่านเก่าของผู้ใช้คนก่อนหน้าจะไม่สามารถนำมาล็อกอินเข้าเครื่องได้อีกต่อไป

#### AC-3.4: การบังคับตัดการเชื่อมต่อเมื่อหมดเวลา (Forced Disconnection on Expiry)
* **Given (กำหนดให้):** ผู้ใช้ยังคงเปิดโปรแกรมรีโมทค้างไว้จนกระทั่งเวลาการจองหมดลง (00:00)
* **When (เมื่อ):** ระบบตรวจพบว่าหมดเวลาเซสชัน
* **Then (ผลที่ต้องเกิดขึ้น):**
  - Host Agent สั่งตัดการเชื่อมต่อของโปรแกรมรีโมททันที (Session Terminated)
  - หน้าจอโปรแกรมรีโมทฝั่งผู้ใช้ต้องขึ้นสถานะขาดการเชื่อมต่อ (Disconnected)

### 2.4 โมดูลที่ 4: หน้า Dashboard ผู้ดูแลระบบ (Admin Dashboard)

#### AC-4.1: การแสดงสถานะเครื่องและคิวแบบ Real-time (Live Fleet Overview)
* **Given (กำหนดให้):** ผู้ดูแลระบบ (Admin) เข้าสู่ระบบและเปิดหน้า Admin Dashboard
* **When (เมื่อ):** มีการเปลี่ยนแปลงสถานะเครื่อง (เช่น มีคนเริ่มใช้งาน, กำลังรีเซ็ต, หรือเครื่อง Offline)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - หน้า Dashboard ต้องอัปเดตสถานะของเครื่องทุกเครื่องโดยอัตโนมัติภายใน 3-5 วินาที
  - แสดงรายละเอียด: ชื่อเครื่อง, IP, โปรแกรมรีโมท, สถานะปัจจุบัน, ชื่อผู้ใช้งานปัจจุบัน, และเวลาที่เหลือ

#### AC-4.2: การสั่งตัดการเชื่อมต่อแบบฉุกเฉิน (Admin Force Disconnect)
* **Given (กำหนดให้):** มีเซสชันการใช้งานที่มีปัญหา หรือผู้ใช้ทำผิดนโยบาย
* **When (เมื่อ):** Admin กดปุ่ม "Force Disconnect" บนการ์ดของเครื่องนั้น และกดยืนยัน
* **Then (ผลที่ต้องเกิดขึ้น):**
  - การเชื่อมต่อรีโมทของผู้ใช้ถูกตัดทันที
  - เซสชันถูกปิด และระบบส่งคำสั่งเข้าสู่กระบวนการ Reset ทันที
  - บันทึกการกระทำลงใน Audit Log

#### AC-4.3: การสั่งรีเซ็ตเครื่องทันที (Admin Force Reset)
* **Given (กำหนดให้):** เครื่องอยู่ในสถานะใดๆ ที่ต้องการรีเซ็ตใหม่
* **When (เมื่อ):** Admin กดปุ่ม "Force Reset"
* **Then (ผลที่ต้องเกิดขึ้น):**
  - Host Agent บนเครื่องปลายทางเริ่มกระบวนการ Reset ทันทีโดยไม่ต้องรอจบคิว
  - สถานะบนหน้า Dashboard เปลี่ยนเป็น `Resetting`

#### AC-4.4: การสลับโหมดบำรุงรักษา (Toggle Maintenance Mode)
* **Given (กำหนดให้):** แอดมินต้องการปิดปรับปรุงเครื่องชั่วคราว
* **When (เมื่อ):** Admin กดปุ่ม "Set Maintenance"
* **Then (ผลที่ต้องเกิดขึ้น):**
  - เครื่องถูกเปลี่ยนสถานะเป็น `Maintenance`
  - ระบบปิดกั้นไม่ให้ผู้ใช้ทั่วไปจองคิวเครื่องนี้ได้จนกว่าจะกด "Enable Available"

#### AC-4.5: การตรวจสอบประวัติและ Log (Audit Logs & Reports)
* **Given (กำหนดให้):** Admin เปิดแท็บ "Audit Logs"
* **When (เมื่อ):** มีเหตุการณ์สำคัญเกิดขึ้นในระบบ (เช่น Booking, Release, Force Disconnect, Reset Success/Failed)
* **Then (ผลที่ต้องเกิดขึ้น):**
  - รายการ Log แสดง วัน-เวลา, ผู้กระทำ (Actor), กิจกรรม (Action), เครื่องเป้าหมาย (Target Host) และสถานะผลลัพธ์ อย่างถูกต้องและครบถ้วน

## 3. เกณฑ์การยอมรับข้อกำหนดที่ไม่ใช่เชิงหน้าที่ (Non-Functional Acceptance Criteria)

| รหัส | หัวข้อเกณฑ์การยอมรับ | เกณฑ์การผ่านการทดสอบ (Pass Criteria) | วิธีการทดสอบ (Verification Method) |
| :--- | :--- | :--- | :--- |
| **NF-AC-1** | เวลาตอบสนองของระบบ (API Latency) | API การจอง, ดึงสถานะคิว, และคืนเครื่อง ต้องตอบสนองภายในเวลา **< 500 ms** ในสภาวะโหลดปกติ | รันทดสอบด้วย Postman / Load Testing Tool |
| **NF-AC-2** | ระยะเวลาการรีเซ็ตเครื่อง (Reset Duration) | สคริปต์ทำความสะอาดและกู้คืน Baseline ต้องทำงานเสร็จสิ้นภายในเวลา **< 60 วินาที** | จับเวลาการรันสคริปต์ Reset ตั้งแต่เริ่มจนสถานะเป็น Available |
| **NF-AC-3** | ความสะอาดของข้อมูล (Data Sanitization) | ตรวจสอบโฟลเดอร์ Temporary, Downloads, Browser History ไม่พบไฟล์หรือ Credential ของผู้ใช้คนก่อนหน้า | ทำการตรวจสอบไฟล์และ Registry/Config บน Host หลัง Reset |
| **NF-AC-4** | การตรวจจับสัญญาณขาดหาย (Heartbeat Detection) | เมื่อดึงสายแลน/ปิด Agent เซิร์ฟเวอร์ต้องปรับสถานะเป็น `Offline` ภายในเวลา **< 30 วินาที** | จำลองการหยุดทำงานของ Host Agent แล้วสังเกต Dashboard |
| **NF-AC-5** | ความเข้ากันได้ของ UI (Cross-device Usability) | หน้าเว็บทั้งฝั่ง User และ Admin ต้องแสดงผลและใช้งานได้ถูกต้อง ไม่ล้นจอ บนความละเอียดตั้งแต่ Desktop (1920x1080) ถึง Tablet (768x1024) | ตรวจสอบผ่าน Browser Responsive Mode บน Chrome/Firefox/Safari |
